# Seer Agent v2: causal replay core (Slice 1)

`seer_agent.v2` is the first slice of the v2 architecture: one owner, bounded inputs, explicit coverage and a reducer that never reads the future. It sits next to the 0.2 runtime and does not change it. Slice 2 adds the scheduler and the Intention, Question and Episode records; Slice 3 connects a real worker.

## Modules

| Module | Holds | Rule |
| --- | --- | --- |
| `clock.py` | `CausalClock`, `CausalViolation` | The replay cutoff in milliseconds. Every reader calls `check(available_at_ms)`; a read past the cutoff raises `CausalViolation`, an `AssertionError` |
| `records.py` | `Frame`, `Watch`, `InferenceRequest`, `InferenceResult`, `Trace`, `RESULT_SCHEMA`, `PRIORITIES` | Values only. A frame carries `captured_ms` and `published_ms`; a watch fixes predicate, candidate set (always including `insufficient_visibility`), threshold, margin and freshness |
| `source.py` | `BoundedSource`, `EvidenceLost` | Ring buffer for one source session. Duplicates are dropped, frames are listed in capture order after their publish time until the core acknowledges them, unpinned frames leave after `retention_ms` or when the ring is full |
| `worker.py` | `Worker`, `FakeWorker` | Workers return data and latency. The fake worker follows a script keyed by the requested interval and counts its calls |
| `store.py` | `ReplayStore` | SQLite tables for frames, coverage, evidence, manifests, jobs, attempts, situations, alternatives, observations, estimates, checks, questions, traces and the search index. Guarded readers: `frames`, `evidence`, `result`, `coverage`, `search` |
| `core.py` | `ReplayCore` | The only writer: intake, requests, job runs, recovery and the six-step reducer |

## Causal contract

Time is integer milliseconds on the replay timeline. The harness advances `CausalClock`; the core never does.

- A frame observes the instant `captured_ms` and stands for the sampling period that ends there, so its coverage is `[captured_ms - period_ms, captured_ms]`. `published_ms >= captured_ms` is required, which is the research protocol's `end_s <= available_at_s`. `BoundedSource.readable` returns a frame only once `published_ms <= cutoff`, and `ReplayCore.ingest` refuses a frame published after the cutoff.
- Evidence handles are readable from `available_from_ms` (publish) to `available_until_ms` (publish plus retention) unless a job pinned them. Pinned bytes are capped by `pin_budget_bytes`. A request over the cap is refused with `pin_budget_full` and an open question `evidence_lost_before_inspection`; frames that expired before a look was requested are recorded the same way and the look proceeds on what remains.
- A worker result becomes readable at `started_ms + latency_ms`. `reduce_pending` ignores results whose availability time is after the cutoff and `ReplayStore.result` raises before then.
- The search index is appended only by the reducer (step 3), and `search(until_ms)` refuses to look past the cutoff. Nothing precomputes the future.
- Coverage levels are `captured`, `signal` and `inspected`; `ReplayStore.coverage` returns explicit `unknown` segments for everything else. An unobserved interval never becomes an estimate.

## Jobs and the reducer

`request(watch_id, from_ms, to_ms, deadline_ms=..., kind=..., priority=...)` pins the frames captured in the interval and queues one logical job. The job id is a digest of watch, revision, kind and handles, so repeating a request is idempotent. `run_pending` runs one job at a time in fixed priority order (reserved coverage first, housekeeping last, earliest deadline within a class), stores the raw result on the attempt and does not reduce it. A worker exception or an owner restart gives the job one more local attempt within its deadline (`MAX_ATTEMPTS = 2`); a schema error is a result, not a retry reason. A partial unique index keeps one valid result per logical job.

`reduce_pending` reduces each stored and available result in one transaction with six named steps, `_step1_validate` to `_step6_open_questions` in `core.py`:

1. Validate provenance (model id), availability cutoff, quality (JSON schema and candidate set), job identity and watch revision. Hard failures end as `rejected:<code>`; a stale watch revision or a foreign owner epoch continues as history.
2. Attach the result to the capture span of the inspected frames and write `inspected` coverage. The time inference finished is never used for this.
3. Record the observation as support for the picked candidate and contradiction for the others. A second result over the same frame set is a repeat, not a new observation.
4. Update the current estimate only when the result is applicable, not older than the current estimate's interval and within `freshness_ms`; otherwise store it as history with the reason.
5. Keep every alternative of the candidate set and record why the situation revision changed.
6. Open a `recheck_next_frame` check when the top two scores are within `margin`, a `prior_free_verify` check when the current hypothesis changed, and a `not_decidable` question when the result is unknown or insufficient visibility.

Every stored result ends in one `Trace`: source, session, sequence range, job and attempt, mission version, watch revision, context version (the committed snapshot the job was requested against), owner epoch, worker model id, queue and inference time, evidence manifest reference and outcome. Expired and failed jobs get a trace with attempt 0 or the last attempt and an open question.

## Running the tests

```sh
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe -e . pytest
PYTHONUTF8=1 .venv/Scripts/python.exe -m pytest -q tests/v2
```

`tests/v2/test_v2_scenarios.py` holds the four Slice 1 scenarios (duplicate and out-of-order input, outage, restart before reduction, backlog) and the restart retry rule. `tests/v2/test_v2_contract.py` covers reads past the cutoff, the pin budget, retention loss, stale watch revisions, rejected results, questions and checks, and the bounded source. Fixtures are synthetic: one camera, one session, frames with a size and a label instead of pixels.

## Not in this slice

Intention, the operator Question record, Episode, the budget ledger and admission queue, routine hypotheses, operator answers, delivery and the real worker belong to Slices 2 and 3. The bounded source keeps frames in memory; the client ring buffer and the `media.*` calls replace it in Slice 5.
